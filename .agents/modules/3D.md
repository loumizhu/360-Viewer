# 3D Module Context

**Files:** `viewer3d.js`, `virtual-visit-360.js`, `viewer.js`, `viewer-pan-zoom.js`, `axonometric-scrubber.js`

## Boundaries & Contracts
- The 3D layer handles rendering, raycasting, and camera manipulation.
- It MUST NOT directly parse or fetch raw database data; it should rely on the Data module.
- **Namespace:** We are migrating to exposing methods on `window.App3D = { ... }`.
- **Event Bus:** Listen for events like `updateFilteredHighlight` to trigger visual changes (like dimming units).

## Design Constraints
1. **Raycasting:** Hovering over meshes applies effects. When hovering out, `clearAllEffects()` MUST be called. Always properly dispose of old geometry and materials (`geometry.dispose()`, `material.dispose()`) to prevent WebGL memory leaks.
2. **Model Integrity:** Do not modify the original `.gltf` model files. All visual changes (like coloring available units green) must be done via material overrides at runtime.
3. **Virtual Visit:** Relies on auditing `[clientID]/360-Virtual-Visit/` for equirectangular panoramas.
